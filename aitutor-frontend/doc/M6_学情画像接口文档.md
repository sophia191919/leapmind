# M6 学情画像前后端接口文档

> 版本：1.0  
> 前端分支：`agent/m6-learning-profile-frontend-v2`  
> 后端基线：`backend-M6`（2026-07-26）  
> 基础地址：开发环境由 `JAVA_API_TARGET` 指定，默认 `http://localhost:8080`

## 1. 统一约定

- 请求和响应使用 UTF-8 JSON。
- 需要登录的请求携带 `Authorization: Bearer <token>`。
- 日期使用 `yyyy-MM-dd`，时间使用 ISO 8601，例如
  `2026-07-26T20:30:00`。
- 百分比字段统一返回 `0`～`100` 的数字，不返回带 `%` 的字符串。
- 当前 Java 后端统一响应结构：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1785076800000
}
```

前端兼容裸数据、Axios `{ data }` 和上述 `ApiResponse` 包装，但推荐后端统一使用
`ApiResponse<T>`。

## 2. 当前后端已实现接口

### 2.1 查询待复习提醒

`GET /api/user-profile/{userId}/review-reminders`

返回待复习记录，后端按计划日期升序、优先级降序排列，包含逾期记录。

```json
{
  "code": 200,
  "message": "查询待复习提醒成功",
  "data": [
    {
      "id": 100,
      "userId": 1,
      "courseId": "course-001",
      "reminderType": "SPACED_REPETITION",
      "content": "复习二叉树的遍历",
      "scheduledDate": "2026-07-27",
      "priority": 2,
      "isReviewed": 0,
      "reviewedAt": null,
      "createdAt": "2026-07-26T10:00:00"
    }
  ],
  "timestamp": 1785076800000
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `reminderType` | string | `REVIEW`、`RECALL` 或 `SPACED_REPETITION` |
| `priority` | integer | `0` 普通、`1` 重要、`2` 紧急 |
| `isReviewed` | integer | `0` 待复习、`1` 已复习 |

### 2.2 标记已复习

`POST /api/user-profile/{userId}/mark-reviewed`

```json
{
  "reminderId": 100,
  "notes": "已经掌握"
}
```

`reminderId` 必填。成功时 `data` 返回更新后的复习提醒；提醒不存在或不属于该用户时返回
HTTP 400。

### 2.3 查询复习历史

`GET /api/user-profile/{userId}/review-history`

响应 `data` 为 `ReviewReminderVO[]`，字段与 2.1 相同；当前排序为未复习记录在前、已复习记录在后。

### 2.4 采集学习事件

`POST /api/events/collect`

```json
{
  "module": "M2",
  "eventType": "EXERCISE_SUBMITTED",
  "userId": 1,
  "eventData": "{\"courseId\":\"course-001\",\"knowledgePointId\":\"ds-tree\",\"correct\":true}",
  "eventTime": "2026-07-26T20:30:00"
}
```

`eventData` 当前是 JSON 字符串，不是嵌套对象。`eventTime` 省略时由后端填写当前时间，
`processed` 省略时默认为 `0`。

相关管理接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/events/collect/batch` | 批量采集事件 |
| GET | `/api/events/unprocessed/{module}` | 查询模块未处理事件 |
| GET | `/api/events/user/{userId}` | 查询用户学习事件 |
| PUT | `/api/events/{eventId}/processed` | 标记事件已处理 |

## 3. M6 前端联调所需接口

当前学情画像页面会并行请求以下三个地址：

| 状态 | 方法 | 路径 | 用途 |
|---|---|---|---|
| 待补充 | GET | `/api/user-profile/{userId}` | 用户画像概览、雷达图、学习时间线 |
| 待补充 | GET | `/api/user-profile/{userId}/knowledge-status` | 知识树及知识点详情 |
| 已实现 | GET | `/api/user-profile/{userId}/review-reminders` | 复习提醒 |

前两个接口未在当前 `backend-M6` 控制器中实现。接口缺失或字段不完整时，前端会显示
“演示数据”标记，不会阻断页面。

## 4. 错误响应

| HTTP 状态 | `code` | 场景 |
|---|---:|---|
| 400 | 400 | 参数错误、提醒不存在、越权访问其他用户提醒 |
| 401 | 401 | Token 缺失或失效 |
| 404 | 404 | 用户或知识点不存在 |
| 500 | 500 | 服务内部错误 |

示例：

```json
{
  "code": 400,
  "message": "复习提醒ID不能为空",
  "data": null,
  "timestamp": 1785076800000
}
```

## 5. 联调验收

1. 使用真实 `userId` 打开“学情分析”，三个请求均返回 HTTP 200。
2. 页面不再显示“演示数据”提示。
3. 知识树节点可进入详情页，掌握度、趋势和历史数据与接口一致。
4. 逾期提醒能正常展示，标记复习后从待复习列表移入历史记录。
5. 任何单个接口失败时页面有降级数据，控制台能定位失败的接口。
