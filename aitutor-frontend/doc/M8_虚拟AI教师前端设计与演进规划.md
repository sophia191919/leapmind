# M8 虚拟 AI 教师前端设计与演进规划

> 模块负责人：欧俊濠  
> 模块名称：M8 虚拟 AI 教师·优化  
> 当前技术路线：React 19 + Three.js + VRM 3D + Web Audio API  
> 文档状态：M8-V1.1 前端与 Java 接口已实现，等待运行环境及 Python 真实数据联调

---

## 1. 模块目标

M8 的目标不是单独展示一个 3D 人物，而是把虚拟教师建设成一套可复用的教学能力：

1. 用户可以选择并保存自己喜欢的教师形象和音色。
2. 讲课页可以嵌入同一个虚拟教师组件。
3. 教师说话时具有口型、表情、视线和教学动作。
4. TTS、情绪分析、动作指令和 PPT 播放可以在统一时间轴上协同。
5. 模型加载失败或低性能设备无法运行 WebGL 时，课堂核心功能仍然可用。

### 1.1 M8 前端三项正式交付物

| 交付物 | 当前状态 | 说明 |
|---|---|---|
| VRM 虚拟教师渲染组件 | 第一版完成 | 支持模型加载、切换、卸载和错误状态 |
| 口型同步与表情动画 | V1.1 完成 | 支持音素时间轴、频谱回退、五种表情和动作调度 |
| 形象选择页与讲课页嵌入 | 第一版完成 | 用户选择可保存并应用到讲课页 |

## 2. 当前前端效果

当前形象选择页采用与 LeapMind 现有页面一致的紫蓝色渐变和玻璃拟态风格。

### 2.1 页面布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 返回   M8 · 虚拟 AI 教师             VRM 3D · 口型 · 表情    │
├─────────────────────────────────┬────────────────────────────┤
│                                 │ 教师形象                   │
│                                 │ ┌────────────────────────┐ │
│         VRM 3D 实时预览          │ │ 小跃  亲切活泼          │ │
│                                 │ ├────────────────────────┤ │

│                                 │ ├────────────────────────┤ │
│                                 │ │ 星澜  自然耐心          │ │
│                                 │ └────────────────────────┘ │

```

### 2.2 已实现的交互

- 首页“虚拟教师”按钮进入形象选择页。
- 点击教师卡片后立即切换左侧 VRM 模型。
- 可直接点击“微笑、思考、强调”预览人物表现。
- 保存后将形象偏好写入后端；后端未上线时自动保存在浏览器。
- 进入讲课页时读取已保存形象，不再固定使用同一个模型。
- AI 回答完成后调用 M8 TTS；M8 TTS 不可用时兼容旧语音接口。
- 后端返回情绪、动作和音素时间轴后，教师按时间同步播报。

## 4. 当前能力与不足

| 能力 | 当前实现 | 主要不足 |
|---|---|---|
| 模型选择 | 3 个本地 VRM 模型 | 缺少真实缩略图、搜索和分页 |
| 模型加载 | 异步加载和错误提示 | 单个模型约 15–16MB |
| 用户偏好 | 后端优先、本地回退 | 接口字段仍需与 Java 端确认 |
| 表情 | neutral、happy、angry、sad、relaxed | 部分模型表情权重存在差异 |
| 情绪映射 | smiling、curious、serious 可映射并可手动预览 | 还没有情绪强度和持续时间 |
| 口型 | 优先使用音素时间轴，缺失时频谱估算 | 等待 Python 真实音素数据联调 |
| 动作 | 支持语义动作定时调度和六种头部动作 | pointing_board 暂时降级为抬头，缺少手臂动作 |
| 待机 | 眨眼、注视、待机动画 | 长时间运行仍需性能测试 |
| TTS | M8 接口优先、旧接口回退 | 尚未验证流式音频 |
| 异常降级 | 模型失败提示、TTS 回退 | 还缺少 2D 静态形象降级 |

## 5. 建议的演进方向

### 5.1 P0：接口联调与功能闭环

P0 是 M8 达到“可验收”必须完成的内容。

#### A. 固化 Java 接口契约

- 获取可用形象列表。
- 获取当前用户形象偏好。
- 保存用户形象和音色偏好。
- 提交 TTS 合成请求。
- 支持音频文件或音频 URL 两种返回方式。

#### B. 接入 Python 动画分析结果

前端解析、规范化和播放调度已完成，当前等待 Python 返回真实数据。

Python 建议返回：

```json
{
  "expression": {
    "type": "smiling",
    "intensity": 0.75
  },
  "gestures": [
    {
      "type": "emphasizing",
      "startMs": 820,
      "durationMs": 1100
    }
  ],
  "phonemes": [
    {
      "value": "a",
      "startMs": 120,
      "endMs": 260
    }
  ]
}
```

#### C. 建立统一播放状态

建议状态：

```text
idle → loading → speaking → paused → interrupted → idle
                     └──────────────→ error
```

必须保证：

- 用户打断时，音频、口型、表情和动作同时停止。
- 恢复讲课时，从正确的 PPT 片段继续。
- 连续点击播放不会产生两条音频或两个渲染循环。

### 5.2 P1：教师表现力升级

#### A. 音素级口型

当前方案根据音量和频谱猜测元音，优点是无需后端数据，缺点是准确率有限。

演进方案：

1. Python 返回音素及时间区间。
2. 前端将音素映射为 VRM Viseme。
3. 使用音频播放时间驱动口型权重。
4. 在音素之间进行 60–100ms 平滑过渡。

建议映射：

| 音素示例 | VRM 嘴型 |
|---|---|
| a、ai、an | `aa` |
| i、yi | `ih` / `ee` |
| u、wu | `ou` |
| o、ong | `oh` |
| 静音、停顿 | 全部归零 |

#### B. 教学动作库

建议至少制作以下动作：

| 动作 | 标识符 | 使用场景 |
|---|---|---|
| 轻微强调 | `emphasizing` | 讲解重点 |
| 指向黑板 | `pointing_board` | 对应 PPT 内容 |
| 双手展开 | `explaining` | 展开概念 |
| 鼓励点头 | `encouraging` | 学生回答正确 |
| 思考姿态 | `thinking` | 等待或分析问题 |
| 欢迎挥手 | `greeting` | 进入课堂 |

动作资源建议使用 `.vrma`，避免在代码中手写大量骨骼关键帧。

#### C. 表情强度

把当前“表情枚举”升级为：

```json
{
  "type": "happy",
  "intensity": 0.7,
  "fadeInMs": 180,
  "holdMs": 1600,
  "fadeOutMs": 300
}
```

这样可以避免所有微笑、严肃和好奇表情都使用相同强度。

### 5.3 P1：形象选择体验升级

- 为每个模型生成统一角度的头像缩略图。
- 增加“试听音色”按钮。
- 增加教师标签：亲切、严谨、活泼、耐心。
- 保存前展示“形象 + 音色 + 语速”组合。
- 支持恢复系统默认教师。
- 在保存成功后提供明确反馈。
- 移动端将左右布局改为上下布局并减少 3D 预览高度。

### 5.4 P1：性能优化

当前 6 个 VRM 模型大小约为 15–16MB/个，属于主要性能风险。

建议：

1. 使用 VRM/GLB 纹理压缩。
2. 将大纹理转换为 WebP 或 KTX2。
3. 控制贴图尺寸，普通课堂模型建议不超过 2048×2048。
4. 形象列表只加载缩略图，用户选中后才加载 VRM。
5. 模型和 Three.js 模块按页面懒加载。
6. 静止时降低渲染帧率，页面不可见时暂停渲染。
7. 将模型资源放入 CDN 或 MinIO 并配置长期缓存。

目标指标：

| 指标 | 目标 |
|---|---|
| 形象选择页 UI 首次显示 | ≤ 1.5 秒 |
| Wi-Fi 环境模型首次可见 | ≤ 4 秒 |
| 已缓存模型切换 | ≤ 1 秒 |
| 桌面端稳定帧率 | ≥ 45 FPS |
| 普通笔记本内存增量 | ≤ 250MB |
| 页面离开后残留渲染循环 | 0 |

### 5.5 P2：智能教学行为

- 根据 PPT 当前页确定教师站位和指向方向。
- 讲到公式或图片时自动转身/指板。
- 学生长时间无操作时主动提醒。
- 根据学生答题结果选择鼓励或纠正语气。
- 根据课程类型自动选择服装、语速和动作密度。
- 增加“严谨模式、活泼模式、陪伴模式”。

### 5.6 P2：可访问性与降级

- 支持“减少动画”系统设置。
- 提供字幕并高亮当前播报句子。
- 允许关闭背景动作，减少眩晕感。
- WebGL 不可用时显示 2D 教师头像。
- TTS 失败时继续显示文字，不阻塞课堂。
- 模型加载失败时提供重新加载和切换教师按钮。

## 6. 建议接口契约

> 以下为前端建议，最终以 Java 后端确认后的接口文档为准。

### 6.1 获取形象列表

```http
GET /api/virtual-teacher/avatars
```

```json
{
  "code": 200,
  "data": [
    {
      "id": "teacher-001",
      "name": "小跃",
      "description": "亲切活泼，适合语言与通识课程",
      "modelUrl": "https://cdn.example.com/teacher-001.vrm",
      "thumbnailUrl": "https://cdn.example.com/teacher-001.webp",
      "voiceType": "young-female-warm",
      "accent": "普通话",
      "enabled": true,
      "version": "1.0.0"
    }
  ]
}
```

### 6.2 获取用户偏好

```http
GET /api/virtual-teacher/preference
```

```json
{
  "code": 200,
  "data": {
    "avatarId": "teacher-001",
    "voiceType": "young-female-warm",
    "speed": 1.0
  }
}
```

### 6.3 保存用户偏好

```http
PUT /api/virtual-teacher/preference
Content-Type: application/json
```

```json
{
  "avatarId": "teacher-001",
  "voiceType": "young-female-warm",
  "speed": 1.0
}
```

### 6.4 TTS

```http
POST /api/virtual-teacher/tts
Content-Type: application/json
```

```json
{
  "courseId": "course-1001",
  "text": "同学们，我们来看一下这个知识点。",
  "voiceType": "young-female-warm",
  "speed": 1.0,
  "stream": false
}
```

后端可以直接返回音频，也可以返回：

```json
{
  "code": 200,
  "data": {
    "audioUrl": "https://minio.example.com/tts/abc.mp3",
    "durationMs": 3250,
    "cacheHit": true
  }
}
```

## 8. 验收标准

### 8.1 功能验收

- 用户可以查看、切换和保存教师形象。
- 刷新或重新登录后仍能恢复用户偏好。
- 保存的形象在讲课页正确显示。
- AI 回答时教师能够播放音频并同步口型。
- Python 返回的情绪可以驱动对应表情。
- 用户打断后音频、口型和动作立即停止。
- 模型或 TTS 失败不会导致页面崩溃。

### 8.2 兼容性验收

- Chrome、Edge 最新稳定版正常运行。
- 1920×1080、1440×900 和常见笔记本分辨率正常显示。
- 窄屏下页面无横向溢出。
- WebGL 不可用时提供清晰提示或 2D 降级。

### 8.3 稳定性验收

- 连续切换模型 20 次不出现黑屏。
- 连续进入/退出讲课页 10 次不产生多重音频。
- 页面离开后麦克风轨道停止。
- 页面离开后 `requestAnimationFrame` 停止。
- 长时间讲课 30 分钟无明显内存持续上涨。

## 9. 推荐开发顺序

```text
阶段 1：确认 Java/Python 数据格式
  ↓
阶段 2：完成真实接口联调
  ↓
阶段 3：接入音素时间轴口型
  ↓
阶段 4：制作并接入教学动作 VRMA

阶段 5：模型压缩、缩略图和加载优化
```

近期最合理的下一步是先确认接口契约，而不是继续堆叠页面效果。接口固定后，前端才能稳定接入流式 TTS、音素时间轴和语义动作。

## 10. 风险记录

| 风险 | 影响 | 处理建议 |
|---|---|---|
| VRM 文件过大 | 首次加载慢、流量高 | 压缩纹理、CDN、按需加载 |
| 不同模型表情名称不一致 | 表情失效 | 建立模型能力清单和兼容映射 |
| 音频与 Python 时间轴来源不同 | 口型错位 | 使用同一次 TTS 结果生成时间轴 |
| 流式音频无法直接解码为完整 AudioBuffer | 不能沿用旧播放方式 | 使用 MediaSource/AudioWorklet 设计 |
| 多个 Viewer 同时存在 | GPU 和内存增长 | 限制活动实例并正确销毁 |
| 浏览器自动播放限制 | 首次 TTS 无声 | 在用户交互后恢复 AudioContext |
| 直接在前端调用第三方 TTS | 密钥泄露 | 所有 TTS 必须经过 Java 后端 |
